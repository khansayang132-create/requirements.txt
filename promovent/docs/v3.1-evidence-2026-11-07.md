
Consequences, enforced in code (`paper.ExecutionAgent.execute(rules=...)`, `execution/engine.py`):
- A trade is placed only if its stop is close enough that a minimum-size order risks ≤ $0.075. Sizes are rounded
  **down** to the lot step and **never enlarged** to reach a minimum; otherwise the trade is rejected and audited.
- Fees + spread consume ~14 % of the per-trade risk budget at the $5 minimum.
- The 2 % total-drawdown lock ($0.60) trips after about 8 full-size losses and needs operator authorization to resume.
- The $5/day aspiration is 16.7 % of equity per day. It is not used anywhere in the decision logic.

## 4. Autopilot, Risk Guardian, persistence and crash recovery (Docker stack)

- Autopilot runs every minute. All gates pass (mode, risk limits, Binance reachable, prices ≤ 150 s old) and the decision
  is **"wait: no strategy has passed live-data validation"**. No paper trade was taken, which is the correct outcome.
- Guardian: equity $30.00, budget $0.075/trade, daily-loss and total-drawdown limits 2 %, policy `protect`.
- Migration: the existing V2.5 PostgreSQL database upgraded 0001 → 0002 on start (23 tables).
- Crash drill: kill switch engaged → worker hard-killed from the host (`kill -9`, exit 137) → Docker restarted it
  (restart count 1) → backend hard-killed and restarted → kill switch **still engaged**, equity intact, research mission
  resumed with the same id and cycle count, autopilot stepping again within a minute. Kill switch then released (audited).
